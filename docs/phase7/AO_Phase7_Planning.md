## 1. 情報 Push（Perplexity）— コストプラン案

公式: [Perplexity Pricing](https://docs.perplexity.ai/docs/getting-started/pricing)（要・最新確認）

料金は **リクエスト単価（検索コンテキスト）+ トークン** の二層。下表は **Low context** 基準の概算。

### プラン A — 軽量（Sonar）

| 項目 | 想定 |
|------|------|
| モデル | `sonar` |
| 1 回あたり | 約 **$0.005〜0.01**（要約 400 token 出力想定） |
| 更新 | 手動 or 30 分ごと 1 クエリ × 8 カテゴリ ≈ 8 req/30min |
| 月額目安（1 ユーザー想定・常時表示しない） | **$5〜15**（300〜1500 req/月） |

向き: ヘッドライン + 1 段落要約。コスト最優先。

### プラン B — 標準（Sonar Pro・Low/Medium）

| 項目 | 想定 |
|------|------|
| モデル | `sonar-pro` |
| 1 回あたり | 約 **$0.015〜0.025** |
| 更新 | 15 分ごと 6 トピック ≈ **576 req/日** |
| 月額目安（単一 API キー・全ユーザー同一キャッシュ） | **$260〜430** |

向き: Yahoo トップに近い「読める」要約。全員同じ JSON を CDN/サーバキャッシュすれば **実質 1 ユーザー分の API 回数** に抑えられる。

### プラン C — 代替（Search API のみ + 自前要約）

| 項目 | 想定 |
|------|------|
| API | Perplexity **Search API** $5 / 1K req + 既存 AO チャット LLM で要約 |
| 1 トピック | 検索 $0.005 + LLM $0.001〜0.01 |
| 月額（B と同更新頻度・キャッシュ共有） | **$50〜120** + 既存 chat トークン |

向き: 見た目は Perplexity 品質に近づけつつ、要約文面は AO 既存モデルで統一。

### プラン D — 非 Perplexity（比較）

| サービス | 単価感 | 備考 |
|----------|--------|------|
| Tavily / Serper 等 | $0.30〜5 / 1K search | 生検索のみ。要約は自前 LLM |
| Brave Search API | 従量 | ニュース向き。要約は自前 |

チャット 1 ターン = 1 枚生成想定。価格は 2026 年初頭の公開情報ベース（**要・契約時再確認**）。

| 項目 | 想定 |
|------|------|

| 1 枚 | **$0.08〜0.20** |
| 月 100 枚 | **$8〜20** |

向き: 販促・完成稿。ユーザー選択の「高画質」オプション。

### プラン D — 会話型編集（Gemini Image）

| 項目 | 想定 |
|------|------|
| API | Gemini 2.5 Flash Image 等 |
| 1 枚 | **~$0.04〜0.07** + 会話トークン |
| 特徴 | 「ここ直して」多ターン。編集 UX 向き |

向き: 同一スレで何度も修正する UI と相性良い。

### API でできること（共通）

- テキスト → 画像（同期 or ポーリング）
- サイズ・アスペクト比の指定（プロバイダ依存）
- 一部モデルの inpainting / 編集（Gemini・GPT Image 系）
- **できない/弱い:** 厳密な字体・長文縦書き・版権キャラの固定（プロンプト + 参照画像で工夫）

## 疑問・殿下への確認事項

### 情報 Push

1. 更新頻度は **リアルタイム** か **15〜60 分キャッシュ** か（コストが 10〜100 倍変わる）。
2. トピックは **固定カテゴリ**（政治・経済・モンゴル関連…）か **ユーザー関心** か。
3. 本文クリックは **外部 URL** のみか、AO 内サマリページを挟むか。
4. Perplexity 必須か、**Search API + 既存 LLM** で十分か。

### 巷間論移設

5. 右サイド幅・折りたたみ。メインは「論タブ + 議事 + チャット」のみにするか。
6. 巷間論は引き続き **Supabase 非永続** でよいか。

### 画像生成論

7. 新 `project_id` 名（例: `ezen` / `gazo`）と他論との **RAG 混在** の有無。
8. 生成画像の **保存先**（Supabase Storage / 一時 URL のみ / localStorage 禁止方針）。
9. **1 日あたり上限**（枚数 or ドル）を設けるか。
10. モデルは **1 本化** か、標準/高画質の **2 段** か。

### 共通

11. Phase 7 で **典籍 RAG を本番チャットに接続** するか（Phase 6 延長）。
12. 右サイド + 画像論の **優先順**（先にレイアウトだけ / 機能同時）。
