## 1. 機能の見取り図

LLM チャットはアプリ全体の一部。機能は互いに疎結合なモジュールとして扱う。

| # | 機能 | 製品入口 | Generic（残置） | 備考 |
|---|------|----------|-----------------|------|
| 1 | **チャット**（LLM） | `/` シェル内 | （将来 `/chat` を検討可） | 論・年代記・僚友会話 |
| 2 | **ナレッジ**（KM・旧講義メーカー） | `/` シェル内埋め込み | `/courses`・`/l` | 講習・管理・公開受講 |
| 3 | **Notebook**（典籍） | 未 | — | Phase 6 系 |
| 4 | **ニュース** | 未 | — | Phase 7 |
| 5 | **オーガナイザー** | 未 | — | 構想のみ |

原則: **左＝横断／メイン＝当該機能の Real estate**。チャットの上下二段を全機能に強制しない。

## 2. AO シェル（契約）

シェル＝横断の額縁。ここに載るものが「AO らしい体験」の共通部分。

| 層 | 内容 |
|----|------|
| **ヘッダ** | 現行ヘッダ |
| **背景** | 現行の世界地図など |
| **左カラム** | 邦主・**機能切替**・使用量／歯車枠・僚友 |
| **メインカラム** | 各機能が自由に使う Real estate（区画は機能ごと） |

### 2.1 シェルに含めないもの

- **ユーザーエリア／ビューエリアの二段分割** — LLMチャット機能の内部レイアウトであり、シェル義務ではない
- 論タブ・年代記・巻物の中身 — チャット（または当該機能）固有

### 2.2 スロット（差し込み口）

スロット＝シェルが空ける機械的な穴。各機能の仕様そのものではない。

例: 機能切替の項目／メインカラム全体／（任意）巻物で「使用⇔設定」を切り替える枠。

中身（吹き出し・講義本文など）は **機能モジュール** が実装する。

### 2.3 機能モジュールの二層

各モジュールは少なくとも次を持つ。

| 層 | 意味 | チャットの例 | ナレッジの例 |
|----|------|--------------|--------------|
| **使用** | 日常の本体 UI | 論＋入力＋履歴 | デフォルト講義の受講面 |
| **設定** | その機能の管理・チューニング | 巻物（グローバル〜令旨〜僚友） | **歯車** → 一覧＋講義管理 |

切替メタファーはモジュールで分ける。チャットは **巻物**（使用⇔設定）。ナレッジは **歯車**（機能内設定）。左カラムの歯車は **全体設定**（準備中）であり、ナレッジ歯車とは別。ナレッジの **巻物** は使用面の **全体構成**（講義の回・節一覧）。

### 2.4 左カラム詳細

| 要素 | 内容 |
|------|------|
| 邦主 | ユーザーペルソナ |
| 機能切替 | 当面 **チャット／ナレッジを常時表示**（ノートブック等は表示のみ可）。歯車による有効化は後 |
| 使用量 | 横断 |
| 歯車 | **全体設定は準備中（無効）**。将来: 有効機能の選択などマスター設定 |
| 僚友 | ペルソナ一覧 |

## 4. ナレッジ（KM）モジュール（2026-08-05 確定）

旧称「講義メーカー」。製品名は **ナレッジ／KM**。チャットに溶かさず、**同じシェルの別モジュール**として載せる。

### 4.1 使用（第1弾）

| 項目 | 決定 |
|------|------|
| 起動 | 左「ナレッジ」→ メインに展開 |
| 構成 | **デフォルト講義の受講面**（一覧は使用の主役にしない） |
| デフォルト講義 | ユーザー設定可能。未設定時は **リスト最上位** |
| 第N回 | 連載記事的 UX（上部に回の目次／タブ）。既存 `CourseLearnView` の回切替を活用 |
| 全体構成 | **巻物**。メインカラム上に中枠 `frame_AS`（スライドなし）。Generic の「構成」ドロワーは `/courses`・`/l` のみ |
| 文末チャット | **第1弾は入れない**（本文のみ）。第2弾以降 |
| 文末チャット構想（第2弾〜） | LLMチャット簡易版・**回専用スレッド** |

### 4.2 設定（第1弾）

| 項目 | 決定 |
|------|------|
| 起動 | **歯車**（使用⇔設定）。設定中は同じ位置が AO 戻る |
| 構成 | **上部: ナレッジ一覧**／**下部: 選択中の講義管理**（現行 `/courses/[id]` 相当） |
| 管理画面の取捨 | 第1弾は **ほぼそのまま**。料金・開発者寄りの削りは第2弾以降 |
| 新規作成など | 現行講義メーカーと同様の遷移を、AO メイン内で展開 |

### 4.3 Generic 残置

| 経路 | 役割 |
|------|------|
| `/courses` 系 | Generic（テンプレ未適用）。デバッグ・旧導線・逃げ |
| `/l` | **第三者公開シェル**（別ユースケース）。当面いじらない。必要時に再設計 |

製品のナレッジは **`/` 埋め込み**であり、左メニューから `/courses` へ飛ばさない。

## 5. チャット機能の内部レイアウト（シェル外・参考）

チャットだけがメインを概ね次のように使う（他機能の義務ではない）。

```
メイン（チャット・使用）
├ ユーザーエリア: 論｜タイトル＋吹き出し｜アイコン・顔・送信
└ ビューエリア: 履歴、または巻物設定／年代記
```

| 種別 | 起動 | 表示 |
|------|------|------|
| チャット設定（巻物） | タイトル右・巻物 | ビュー側・大枠。タブ: グローバル／ヘッダ／モード／令旨／僚友。影は金枠輪郭から外へ（`overlayDropShadow`） |
| 年代記（本棚） | タイトル右・本棚 | ビュー側・大枠。15件／ページ。影は同上 |
| 使用量 | 左・コイン | ビュー側・大枠（巻物設定と同じ）。影は同上 |

大枠: ユーザーエリア外周と機能パネルは `AoTemplateFrame` `frame_AL`。左右余白は `CHAT_AREA_PAD_*` で揃える。

## 9. シェル確定チェックリスト（2026-08-06）

「シェルとして確定する」＝**構造契約＋横断クロム＋デザイントークン／資産の境界**を文書と実装の両方で固定すること。機能モジュールの中身（チャットの論、KM の回目次など）はシェル確定の対象外。

### 9.1 モジュール（機能）とデザイン（テンプレ）の関係

| 関係 | 内容 |
|------|------|
| **ほぼ独立** | 現存・想定機能（チャット／KM／ニュース／オーガナイザ）では、**機能の業務ロジックがテンプレの見た目語彙を強制しない**。デザインは切り出して定義してよい |
| **弱い接点だけ共有** | 機能切替の並び、巻物＝使用⇔設定、大枠でメインを包む、といった**シェル契約のメタファー**だけが共通。モジュールはその上に載る |
| **テンプレが機能を縛らない** | 「上下二段」「連載目次」は各モジュールのレイアウト。テンプレは枠・色・字・アイコン・余白を供給する |

結論: **まずデザイン／シェルを切り出して考えてよい。** ただし「巻物の意味」「左に何が常駐するか」はシェル契約であり、純粋なピクセル定義ではない。

### 9.2 シェルが定義するもの（三層）

```
┌─────────────────────────────────────────┐
│ A. 構造契約（Structure）                  │  ← 何がどこに居るか
├─────────────────────────────────────────┤
│ B. 横断クロム（Chrome）                   │  ← 常に見える枠組み UI
├─────────────────────────────────────────┤
│ C. テンプレ語彙（Tokens / Assets）         │  ← 見た目の部品庫
└─────────────────────────────────────────┘
         ↑ メイン Real estate にモジュールが載る
```

#### A. 構造契約（決め切る対象）

| 項目 | 現状の合意 | 確定時に一文で固定すること |
|------|------------|----------------------------|
| 領域 | ヘッダ／背景／左／メイン | この4つがシェル。それ以外はモジュール |
| メイン | Real estate のみ | **区画（上下二段等）はシェル義務ではない** |
| 機能の二層 | 使用／設定 | チャット＝巻物、ナレッジ＝歯車（左歯車は全体設定で別） |
| 機能切替 | 左メニュー | 第1弾はチャット＋ナレッジ常時。歯車有効化は後 |
| URL | `/` 製品、Generic は `/courses`・`/l` | シェル確定後も維持可 |
| スロット | 機能項目・メイン穴・（任意）設定トグル | 差し込み口の名前と責務 |

#### B. 横断クロム（決め切る／実装で固定する対象）

| 項目 | 中身 | 備考 |
|------|------|------|
| ヘッダ | ブランド・ログイン等 | 現行維持で可 |
| 背景 | 世界地図 | パス・重ね方 |
| 左・邦主 | 顔＋名札＋ルビ | コンポーネント境界 |
| 左・機能切替 | ラベル列＋選択表示 | 選択可能／不能のルール |
| 左・使用量／歯車 | アイコン行 | 歯車＝準備中の状態も契約 |
| 左・僚友 | 一覧 | 「常時全件」等は後で可 |
| メイン外周 | 余白（地図が見える）・大枠の使い方 | モジュールが大枠を使うかは推奨レベルで可 |

#### C. テンプレ語彙（デザイン切り出しの本体）

**トークン（値）**

| 種別 | 例（現行） |
|------|------------|
| 色 | インク `#3D1C08`、金 `#DBB961`／`#C9922A`、紺地（シェル）、面 `#FFFAF2`（一色・グラデなし） |
| タイポ | セリフ本文、ルビ、トラッキング |
| 余白・幅 | 左250／メイン750（PC）、`CHAT_AREA_PAD_*`、カラム gap |
| 影 | 大枠ドロップシャドウ、押し込み inset |
| z-index | ヘッダ／ドロワー／オーバーレイ帯 |

**部品（コンポーネント）**

| 部品 | 役割 |
|------|------|
| 大枠 `AoTemplateFrame` `frame_AL` | `frame_A` 金レール＋ベージュ内塗り（border-image overlay） |
| 吹き出し nine-slice | チャット使用（モジュール寄りだが語彙として登録可） |
| 顔枠・名札 | 邦主／僚友／チャット話者 |
| 羊皮紙 surface | `ao-p5-parchment-surface` |
| アイコン一式 | `ao-action-icons`（巻物・本棚・歯車・コイン等） |

**資産（ファイル）**

| 種別 | 例 |
|------|-----|
| 枠画像 | `/template/frames/`（大枠 Frame_A、ornament は未移行中枠） |
| 背景 | `/template/bg/map-bg1.png` |
| ロゴ | `/template/logo/` |
| ポートレート | `/personas/*`（中身はコンテンツだが「枠に載る」前提はテンプレ） |

### 9.3 シェルが定義しないもの（モジュール／後続）

- チャット: 論列、ユーザー／ビュー二段、令旨タブ中身、年代記リスト
- KM: 受講目次、管理画面の項目取捨、文末チャット
- ニュース／オーガナイザの画面構成
- Generic `/courses` の独自 CSS（テンプレ未適用のまま残置可）
- 歯車マスター設定の中身、認証・マルチユーザー

### 9.4 「シェル確定」の完了条件（提案）

次を満たせばシェル確定としてよい。

1. **§9.2-A** が正本に一文ずつ書いてある（本ドキュメント）  
2. **KM 設定**の最低調整が終わり、左切替→使用／巻物→設定が破綻しない  
3. **クロム（B）** のコンポーネント境界が分かる（左＝常に同じ、メインだけ差し替わる）  
4. **テンプレ語彙（C）** の目録がある（完成実装は後でも、一覧は確定）→ **§10 テンプレ・パーツ台帳**で確定  
5. 「新機能を足すとき」の手順が短い: 機能 ID を足す → メインに使用／設定を載せる → （任意）語彙部品を使う  

デザインのピクセル完全統一や `page.tsx` 分割は **シェル確定の必須条件にしない**（確定後の作業）。

### 9.5 KM 設定を触ってから確定、の意味

殿下の「KM 管理を少し調整したらシェル確定」は、**構造契約の実地検証**として正しい。調整対象の例（シェル本体ではない）:

- 一覧と管理の密度・スクロール
- Generic への逃げリンクの扱い
- 巻物／戻るのラベルと位置

これが安定すれば、A＋B は確定してよい。C の切り出し実装は並行または直後でよい。

## 10. テンプレ・パーツ台帳（2026-08-08）

**位置づけ**: シェル §9-C「テンプレ語彙」の正式版。ここが命名・役割・状態・対応資産の正本。実装（部品の切り出し・`phase5` パスのリネーム・`page.tsx` 掃除）は本台帳に沿って後続で寄せる。命名は暫定確定（後日の変更は容易）。

### 10.0 用語（原語メモ）

- これまで「契約」と呼んでいたものの原語は **contract**（インターフェース仕様の意）。本書では **シェル仕様**／**取り決め** と呼ぶ。
- **シェル** = アプリの外殻（どこに何が居るか）。**テンプレ** = 見た目の部品庫（どう見せるか）。

### 10.1 三層の分担（再掲・要）

| 層 | 持ち主 | 内容 |
|----|--------|------|
| **プリミティブ（見た目）** | テンプレ | 枠・色・字・状態。パーツ本体 |
| **合成（配置）** | **モジュール** | パーツをどう並べるか |
| **中身（コンテンツ）** | モジュール／データ | 実テキスト・画像 |

「パーツを割り当てれば見た目が自動適用」は **プリミティブ層** で成立。**配置と中身はモジュールが持つ**（KM＝縦連載、チャット＝二段、が両立する理由）。

### 11.1 推奨移行順（効率）

| 順 | 作業 | 理由 |
|----|------|------|
| **1** | 本節（規約）の文書確定 | 実装の手戻り防止 |
| **2** | **B′: Tailwind `@theme` 登録＋面 `#FFFAF2` 一色化** | §11.8。見た目は面のみ変化（グラデ廃止） |

ただし A は枠トークン（`ao-frame-tokens.ts`）だけでも着手可能。**見た目の実感を優先するなら A 先も可**だが、総工数は B→A の方が短い見込み。

### 11.4 枠の描画規約（ベンチマーク＝Bubble 成功例）

1. ソース PNG: **外側＝透過、内側＝一色塗りを画像に焼き込み**  
2. CSS: `border-image-slice: … fill`（`sliceFill: true`）  
3. **子要素の CSS 塗りで枠を覆わない**（子は常に border-image より手前のため）  
4. `border-image-repeat: stretch`（`round` は横二重に見えやすい）  
5. 吹き出しの尾は **角スライスに含める**（A=右上／B=左上、`sliceTop` を尾下端以上に）  
6. 大枠のドロップシャドウは **金＋内塗りの輪郭** に `filter: drop-shadow`（`overlayDropShadow`）。矩形 `box-shadow`（border-box）は使わない。  
7. **AO 本番の枠・影調整をマスターとする。** 他テンプレを載せるときは、テンプレ側をこの見え方に合わせる（本番をテンプレに合わせて戻さない）。

採用プリセット: `frame_AL` `frame_AS` `frame_C` `frame_D` `bubble_user` `bubble_system` `label`  
非採用・保留: `frame_B`
